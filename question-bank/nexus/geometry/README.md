# Geometry — Untangle The Nexus import package

Collection `GEO`, version 1.1.0. 105 question sets, 3160 questions, 189 figure files. Generated by
`question-bank/engine/export.py` in the math-lab-app repository; regenerate there rather than editing these files by hand.

This is version 1.1.0. Compared with the previous version: 2480 questions unchanged, 410 revised, 270 new, 25 retired. `CHANGELOG.md` lists every change by question ID; `revisions.json` has the full map.

## Files

| Path | Contents |
|---|---|
| `index.json` | The collection (`id`, `version`), every set with its file, standard, and each section's relation and question IDs, the ID format and the grading rules. |
| `sets/Sxx.json` | One file per question set. Each question is a complete record (see below). |
| `assets/<ID>.svg` / `.png` | The figure for that question (SVG preferred, PNG fallback). Picture choices are `<ID>-A.svg`, `<ID>-B.svg`. |
| `revisions.json`, `CHANGELOG.md` | Changes since the previous version, keyed by question ID (only after a revision). |
| `CORRECTIONS.md`, `COVERAGE.md` | When present: the finding-by-finding correction checklist for a review, and the coverage matrix of requirements and sets. |
| `MANIFEST.json` | Every file in the package with its size and SHA-256, for checking that nothing was lost. |
| `pdf/` | The printable question collection and answer key in 800-page parts. Page numbers match the `page` field. Not needed for import. |

## Importing

1. Read `index.json`. For each entry in `sets`, load its `file`. Set numbers are fixed and need not be consecutive
   (sets added in a revision take the next free number, and appear next to their related sets).
2. Each set file has `sections` in order: MAIN, BACKWARD branches, FORWARD 1, FORWARD 2. `relation` is
   `main`, `backward`, `forward1` or `forward2`. A section's questions all test the same skill and standard.
   Backward branch numbers are also fixed (B1, B3, B4 is possible when a branch was retired).
3. Store each question by `uid` (for example `GEO:S1-M-Q1`), which is unique across all grade collections. `id`
   is unique only within this collection. An ID is never reused for a different skill: when content moves or is
   retired, `revisions.json` says where it went.
4. Copy `assets/` as is and resolve `figure.svg` / `figure.png` (and picture choices' `svg` / `png`) relative to this folder.
5. Optional: check every file against `MANIFEST.json`.

## Question record

| Field | Meaning |
|---|---|
| `uid`, `collection`, `id` | Identity: `uid` = collection + `:` + `id` |
| `set`, `section`, `section_code`, `relation`, `number` | Where the question sits |
| `standard`, `standard_grade`, `domain`, `skill`, `nearest_related` | What it tests |
| `nearest_connection` | Course collections only, on nearest-related forward branches: how the branch connects to the set's MAIN skill |
| `standard_grade` | The grade of a Grade K-8 standard, or `"HS"` for a high-school standard (no grade is assigned) |
| `standard_course`, `standard_level` | High-school standards only: the course this bank places the standard in (Algebra I, Geometry, Algebra II, Probability & Statistics, or Precalculus), and a sentence saying that this is the bank's placement |
| `type`, `response` | `mc` (select one), `tf` (true or false), `sa` (write an answer), `plot` (draw on the figure), `plot_text` (draw on the figure AND write an answer), `work` (write the answer and show the required work) |
| `prompt`, `prompt_markup` | Question text: plain, and with `{a/b}` fraction markup |
| `choices` | `[{letter, text}]` in the order students see; true/false is A. True, B. False. Picture choices add `svg`, `png`, `data` |
| `answer_lines` | Labels of the student's answer blanks, for written answers |
| `correct_letter`, `correct_answer` | The answer. For `plot`, `correct_answer` describes a correct drawing; for `plot_text` it is the written answer |
| `drawing_answer` | `plot_text` only: what a correct drawing shows |
| `required_method` | `work` only: what the shown work must use; the final answer alone is partial credit |
| `grading_note` | Accepted alternatives and what an explanation must include |
| `figure` | `svg`, `png`, `kind`, `description` (plain text), `blank_for_drawing`, and `data` (the values the figure is drawn from) |
| `revision` | `unchanged`, `revised` or `new` compared with the previous version |
| `page` | Page in the PDFs |

## Grading

`grading_rules` in `index.json` applies to every question. Multiple choice and true/false compare letters.
Written answers accept any mathematically equivalent form unless the question asks for a specific form. A `plot`
drawing is judged against `correct_answer`; a `plot_text` response needs both the drawing (`drawing_answer`) and the
written answer (`correct_answer`). A `work` response needs the method in `required_method`. Explanations must include
what `grading_note` lists.

## Geometry additions

| Path or field | Contents |
|---|---|
| `BRANCH_MAP.json` | Every set's MAIN target skill, the subskills it covers, and each branch's teacher metadata (also in each set file as `sections[].branch`). |
| `VALIDATION.md` | The automatic checks run on this release and their results. |
| `COVERAGE.md` | Every standard, every subskill (subpart or distinct demand) with its set and MAIN IDs, and each set's branches. |
| `CHANGELOG.md` | Changes by question ID. |
| set file `strand`, `target_skill`, `covers` | `core` or `advanced` (the ADVANCED EXTENSION of (+) standards); the one skill MAIN measures; subskill IDs. |
| question `strand`, `set_target`, `target_skill`, `alignment_type`, `course_level` | Strand; the set's target; the skill this section measures; how the section's standard relates to it (direct MAIN, exact or supporting prerequisite, or the forward progression type with direct / nearest related); the course label. |
| question `question_page`, `answer_key_page` | Page in each PDF (always equal). |
| `sections[].branch` | Backward: `alignment` (exact or supporting), `rationale` (obstacle, why it matters, evidence collected), `source`. Forward: `progression`, `connection` (direct or nearest related), `new_demand`, `course`, and for FORWARD 2 `builds_on`. Every section: `plus_standard` (true when its standard is a Common Core (+) standard; seven core sets have a (+) FORWARD 2). |
| `revisions.json` | One entry per question ID since the published 1.0.0: status (unchanged, revised, new, retired), the correction-report finding codes, the reason, and `moved_from` / `moved_to` for content that moved to a new set. |
| answer key (`Geometry_Answer_Key.json` / `.csv`, outside this package) | Adds `figure_svg`, `figure_png` (paths inside this package), `figure_description`, and `figure_data` for every question with a figure, keyed by `uid`; the CSV appends these as the last columns, and no existing column was renamed. |

Question types used: `sa`, `mc`, `tf`, `work` (proofs, derivations, and explanations: the student shows the argument in a work
box; `required_method` and `grading_note` give the essential criteria, accepted alternatives, and invalid arguments), and
`plot` (drawings and compass-and-straightedge constructions on the figure; the grading note lists the construction marks
to check). These need a person or a drawing surface to grade. No other new type is used, so the existing importer applies.
